# Fusion personal activity log

Frontend: `dist/activity.js` sends only events for a personal invitation. Normal visits have no telemetry. `activity-admin.html#key=…` displays the private timeline. Tokens are random 256-bit capabilities; only SHA-256 digests live in the database. Never commit invitation or administrator tokens. Anyone holding a link can exercise its role; this is link attribution, not verified personal identity.

The Edge Function checks its own `x-fusion-token` credential before any read/write, so `verify_jwt=false` is intentional. It uses server-managed Supabase secrets; no database key is shipped to the frontend. REST table access and summary execution are revoked from anon/authenticated; RLS remains enabled with no public policies. The advisor's RLS-without-policy INFO is intentional deny-by-default, not a missing public policy. See https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy . An unrelated pre-existing Auth leaked-password warning is outside this feature (https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

Server timestamps are authoritative receipt times; client timestamps provide offline event time. Client activity is self-reported, not anti-cheat evidence. No input values, IP addresses or fingerprint identifiers are stored in these tables. The platform may retain its own operational HTTP logs. A random session ID groups visits without identifying a device.

Personal progress is stored under a distinct localStorage namespace. The personal invitation credential stays in the tab's sessionStorage; closing the tab may require reopening the original invitation. Offline events retry every 20 seconds and on visibility/network changes. Keepalive delivery is best-effort; reopening the personal link retries the outbox. Events older than 29 days are discarded from the outbox. Existing ordinary-browser progress and past activity are not imported.

Backend files are a reproducible schema snapshot and the deployed function source, not Supabase CLI migration history. Public registration is not exposed; links are provisioned administratively. Revocation: set `revoked=true` on the selected fusion_track_links row. Existing event history is retained. This affects only that invitation and its matching viewing key, not other applications.
